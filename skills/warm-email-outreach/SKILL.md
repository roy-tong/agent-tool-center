# 暖外联邮件（warm-email-outreach）

替用户写给具体某个人的外联邮件。三条底线，全部来自真实外联的实测教训：

1. **千人千面**：每封邮件至少 1 个可验证的收件人专属细节，换掉收件人名字后邮件必须不成立。队列准入的硬门槛是"有钩子字段"（公开数字/公开引用），这也是回复率的来源（来源：`projects/AgentMeasure/市场推广/发现冲刺-20260919/触达数据库-20260920.md` §4）。
2. **不被识别为 AI / 群发**：收件人（多为工程师、CX 负责人、投资人）对模板邮件的免疫力极高。实测对照：通用问句式冷邮件 0 回复 / 26 封；个性化求评互动 3/3 转化为规格级贡献（来源：`projects/AgentMeasure/市场推广/求评式外联-skill-20260917.md`）。
3. **先抹陌生感、拉距离，再谈正事**：正事（请求）永远放在钩子和桥之后，且请求成本必须低。

本 skill 是所有 1:1 外联邮件的**通用底盘**。求评式（请对方评审仓库/规格/fixture）是它的一个特化模式，已单独成 skill：**expert-review-outreach**——命中求评场景时路由过去，不在此复制。

## 什么时候用 / 怎么路由

- 用本 skill：冷触达、暖回访（有过互动的人）、跟进邮件、商务合作/求介绍、社区/社交渠道的私信（LinkedIn note、Reddit DM、X DM 同构）。
- **路由到 expert-review-outreach**：目标是项目维护者/活跃贡献者，且手里有一个可评审的具体物件（仓库/spec/fixture/validator）。求评场景的七要素和硬门比本 skill 更严，以它为准。
- 归 shuorenhua：非邮件的一般文本去 AI 味。邮件里的 AI 味判定用本 skill 的邮件版分级（致命项和文章不同，见第 2 节）。
- 不适用：群发营销邮件（newsletter、drip campaign）、客服回复、法律/正式函件。

## 1. 发件前研究清单（千人千面的输入）

不研究完不动笔。研究产出直接进输出合同第一件（研究摘要）。

### 1.1 查什么（按优先级，能查到几项算几项）

| 优先级 | 查什么 | 去哪查 |
|---|---|---|
| P0 | 对方**近期**的工作与言论：最近 6 个月的 PR/issue/评论、博文、推文、播客出场、会议 talk | GitHub、个人站、X/LinkedIn、播客 shownotes |
| P0 | **公开数字/原话**：案例页引用、论坛帖原句、性能数字、价格吐槽 | 厂商 customers 页、Reddit/社区帖、G2 评论 |
| P1 | 对方的**处境**：在用什么产品、什么计费模式、临近续约/迁移、团队角色（谁拍板） | 案例内页、LinkedIn 头衔、讨论区语境 |
| P1 | 与我方事物的**真实交集**：我们修过的东西是否在对方栈里、对方是否提过相邻问题 | 我方 repo 的 issue/PR 记录、上游修复清单 |
| P2 | 签名与身份线索：邮箱形态（数字 handle 型退信率 25%+，直接弃）、有无个人站 | SMTP 预验证、Hunter 确认 |

### 1.2 怎么转化成钩子

- **硬钩子（必选其一）**：对方的一个可验证事实，最好带数字或原话——"你在 X 项目里做的那次 Y"、"你案例页里那个 $30k/年 的数字"、"你在论坛写的'点了 Yes 就计费'"。硬钩子必须能在 2 分钟内向第三方指出出处（PR/issue/帖子/案例页链接存在）。
- **处境钩子（强烈建议）**：为什么是**你**——对方的角色/场景让这个问题对他比对别人更尖锐。"你管支持团队，这正是你续约前会被 finance 问的数字"。
- **交集钩子（有则最强）**：我们和对方的真实历史——修过对方在用的库、对方的某条反馈已被采纳、对方曾经回复过我们。交集钩子只准用真实存在的（查记录），编造 familiarity 是最致命的错误。

### 1.3 合格线：最少几个专属细节

- **底线（不过不发）**：1 个硬钩子。只有"I saw your work"级别的泛指 = 没有钩子 = 不发。
- **标准**：硬钩子 1 个 + 处境钩子或交集钩子 1 个。真实高转化样本都是这个配置（来源：`市场推广/发现冲刺-20260919/触达批次1-20260920.md`，每封都引案例页原话数字 + 按对方角色定制请求）。
- **深钩模式**（高价值目标：CEO/CTO/维护者/官方域名）：2-3 个专属细节，逐封人工级研究，每日 ≤10 封（来源：expert-review-outreach 发送纪律）。

### 1.4 当日核实（钩子会腐烂）

写信用到的事实**发送当天再核一遍**。实测教训：两位目标的人物情报在一周内过期——一位已跳槽到厂商侧（钩子方向反了，客户触达变同业触达），一位已离开被引用的公司（案例钩子作废，只能降级重写）。过期的钩子比没有钩子更糟：它证明你没有真的在看对方（来源：`触达批次1-20260920.md` 9/20 人物情报修正记录）。

## 2. 防 AI 识别规则（邮件版）

邮件的致命 AI 味和文章不一样，按以下优先级重排。文章里最致命的是收束腔和总结腔；**邮件里最致命的是通用性和表演性礼貌**——因为收件人第一反应是"这是群发吗/AI 写的吗"，而不是"文笔好不好"。

### 2.1 换名测试（第一优先级，一票否决）

把收件人名字和公司换掉，邮件是否仍然成立？仍然成立 = 模板 = 重写。通过标准：至少有一句话**只能**写给这个人（引了对方的数字/原话/具体处境）。

### 2.2 邮件 AI 味分级（从致命到兜底）

**A 级·一票否决（任一命中即重写，不进入自检）**
- 无锚点赞美："amazing/incredible work"、"Your project is impressive"、中文"久仰大名/拜读了您的大作"（无具体所指）。赞美若不可验证，等于宣布这是模板。
- 万能开头："Hope this email finds you well"、"I hope you're doing well"、"I came across your profile/project"、"冒昧打扰"。第一句必须是钩子或事实，不是问候也不是自我介绍。
- 元话语自证："this is not a blast"、"I'll keep this short"、"抱歉冒昧"——越声明不是群发，越像群发。删除所有关于这封邮件本身的话。
- 空洞 CTA："I'd love to hear your thoughts"、"期待您的回复"作为唯一请求。收件人不知道回什么，就不回。

**B 级·高危（逐条检查，命中即改）**
- 三段排比 / feature bullet / "Not only X but also Y"：1:1 邮件里出现 3 条并列卖点或三个等长段，是 AI 和营销模板的共同指纹。个人邮件不列 bullet，最多一处双元素对比。
- 完美对称与抛光语法：每句差不多长、零口语、零不完美。真人的邮件有长短句落差，允许 "Worth a look?" 这种两个词的句子。
- em dash 密度：本项目外联的门禁明确禁 em dash（AI 指纹）；用句号、逗号或拆句替代（来源：`市场推广/GTM工作区/newoutreach/check_send.py` 及 expert-review-outreach 硬门）。
- 过度礼貌堆叠："I was wondering if perhaps you might..."、中文"不知是否方便劳烦您"。一层礼貌就够，直接说动作。
- 模板句式自指（本项目实测封禁词）：英文 "one boundary I can't settle" / "I'm building" / "a quick yes/no" / "I saw your work" / "context if useful" / "either answer would help" / "I lean A/B"——这些是我们自己早期波次用滥后成为指纹的句子，门禁已封禁，禁止再写（来源：check_send.py `ANTI_TEMPLATE_PHRASES`，违规样本见 `references/before-after.md` 第 1 组）。
- 问句计数失衡：恰好 1 个问句是实测最优；0 个=没有回复入口；>2 个="interview mode"，收件人压力大（来源：check_send.py 反模板结构门）。

**C 级·密度信号（单个可放行，扎堆即改）**
- 渲染词：revolutionize / game-changer / cutting-edge / seamless / 赋能 / 抓手 / 闭环（商务黑话同 shuorenhua 处理）。
- 完美收尾+"Looking forward to hearing from you"式垫片连用。
- 主题行 title case 营销腔（"Revolutionizing Your Workflow Today!"）。

### 2.3 人味从哪来（正向清单）

1. **具体**：数字、原话、文件名、链接。一个真实的 "$30k since April" 顶十句 "great results"。
2. **克制**：50-200 词正文，1 个请求，1 个问句。短本身就是诚意信号（来源：`市场推广/邮件营销-20260910/README.md` 风格纪律）。
3. **允许口语和不完美**："Worth a look?"、"Thanks either way."、开头小写、一句话一段。别抛光到失真。
4. **直接**：先给事实再给判断，不用铺垫句。删掉所有"为了让邮件显得礼貌/完整"而存在的句子。
5. **真实身份**：真名 + 一行身份 + 一个可点开的链接（GitHub/LinkedIn/个人站）。匿名或半匿名外联等于索取（来源：expert-review-outreach 七要素）。
6. **主题行像人写的**：小写、具体、带上下文。实测风格样本："identical sibling spans after a node retry"、"your demo traces, six weeks of standard work later"、"how should an MCP chart server count a retried render"（来源：`邮件营销-20260910/queue_*.txt`）。

词表（中英文各一份、含替代写法）见 [references/ai-tells-en.md](./references/ai-tells-en.md) 和 [references/ai-tells-zh.md](./references/ai-tells-zh.md)。

## 3. 结构法：抹陌生感 → 拉距离 → 再谈正事

展开顺序固定。三层可以短到各一句话，但顺序不能倒。

### 3.1 第一层·抹陌生感（第 1-2 句）

任务：让收件人在 3 秒内确认"这封信是写给**我**的"。
写法：钩子开场——对方的具体贡献/数字/原话，精确到项目名、帖子、案例页。
常见错误：
- 泛指钩子（"I saw your work on X"）——A 级 AI 味。
- 过期钩子——没做当日核实（见 1.4）。
- 钩子之后立刻接自我介绍——顺序错了，先让对方看见自己，再让对看见你。

### 3.2 第二层·拉距离（中间 1-3 句）

任务：回答"为什么是我写信给你"，把陌生人关系降半级。
写法（三选一，按强度）：
1. **交集**：我们的真实历史或我的工作与对方工作的具体接点（"你正在做的 X 正是我们这个 spec 要钉死的边界"）。
2. **处境共鸣**：对方的处境 + 我方一句话定位（含不竞争的补位声明："before or alongside 你已有的东西"）。
3. **坦诚身份**：一行我是谁、在做什么、为什么找到对方（信息量要具体到可点开）。
常见错误：
- 拉距离变自我推销：这一层只许一句话定位，feature 列表零容忍。
- 假熟悉："As a longtime fan of..."——没有交集证据就不装。
- 过长：这一层超过 3 句，收件人已经开始怀疑是 pitch。

### 3.3 第三层·再谈正事（最后 2-3 句）

任务：一个具体的、低成本的、对方有资格回答的请求 + 什么算好回复。
写法：请求精确到物件和判断题（"a quick read of `conformance/vectors/X.json` and one verdict: ..."），并给 2-3 个"好反馈长什么样"的例子，把模糊请求变成收件人立刻知道怎么回的选项（来源：expert-review-outreach 七要素第 4/5 条）。
常见错误：
- 首触就上高成本 CTA（15 分钟通话、注册、demo）。实测被淘汰的早期版本正是 "Worth 15 minutes for you?"（来源：`newoutreach/b_cliff.txt`）。
- 多个请求并排。
- 请求与对方专业身份不匹配（请 CFO 回答语义学问题、请工程师回答预算问题）。

### 3.4 收尾：软 CTA 阶梯（按收件人成本从低到高）

| 级 | CTA | 适用 |
|---|---|---|
| L0 | 无请求，纯给予/闭环（"你的反馈已落仓库，链接在这"） | 暖回访、闭环回报 |
| L1 | 一句话裁决题（"would X be an acceptable middle?"） | 冷触达首选、深钩 |
| L2 | 读一个具体文件 + 一个判断题 | 求评式首触（路由 expert-review-outreach） |
| L3 | A/B 二选一 | 对方忙但可能顺手回 |
| L4 | 转介绍 / 15 分钟通话 / 发数据 | 只在对方已表现兴趣后 |

规则：**首触不超过 L2；信任每多一轮，最多升一级**。实测降 CTA 的正例：对只回过一轮的人，主动撤回"请在 issue 下留评论"的请求，只保留告知（来源：`newoutreach/replies3/david_r1_2026-08-25.md`，草稿修订说明即"降 CTA"）。

### 3.5 署名

真名 + 一行身份 + 一个链接。不堆 title 墙，不放退订脚注（1:1 邮件里 unsubscribe 脚注=群发实锤）。

## 4. 场景包（四个骨架，槽位逐封填实，禁止两封正文相同）

### 4.1 冷触达（无历史）

```
Subject: {对方语境里的具体事物，小写，如 "identical sibling spans after a node retry"}

Hi {名},

{硬钩子 1-2 句：对方的具体贡献/数字/原话，精确到出处}

{拉距离 1-2 句：交集或处境共鸣 + 我方一句话定位（含补位声明）}

{请求：L1/L2 级，一个判断题 + 2-3 个"好回复长什么样"的例子}

{真名 + 一行身份 + 链接}
```
纪律：50-200 词，恰好 1 个问句，无 bullet，无 em dash，无 A/B 级 AI 味。

### 4.2 暖回访（有过互动：回复过、采纳过反馈、见过面/连过线）

核心：**带收据回来**，不是"还记得我吗"。

```
Subject: {对方的那个点 + N weeks/months later，如 "your X, six weeks later"}

Hi {名},

{对方上次的输入现在变成了什么：进了 spec/改了模型/落了仓库，before/after 对照}

{链接：能点开看到对方影响的地方}

{可选的低请求：L0/L1——"one-line comment confirming this captures your point"，且给 opt-out}

{署名}
```
实测样本：Gunjan 两轮深谈后的收口信（改动结构化展示 + 匿名署名告知 + opt-in 询问）、queue_A 的 "DR-005 six weeks later: did the two-state model hold up?"（来源：`newoutreach/replies3/gunjan_r2_2026-08-25.md`、`邮件营销-20260910/queue_A.txt`）。
纪律：对方给的反馈**一周内**落到仓库并有可回链接，再把链接回给对方——闭环本身就是下一次互动（实测：David 的 fixture 从求评到入库 7 天，来源：`市场推广/GTM工作区/leads/v2v3/outreach-playbook-20260919.md` §五）。

### 4.3 求评式（请对方评审仓库/规格/fixture）

**路由到 expert-review-outreach**，按其七要素与硬门执行。判断条件：对方是维护者/活跃贡献者（贡献可具体引用）+ 我方有可评审的具体物件。本 skill 不重复其内容；只补一句：求评信同样要过本 skill 的换名测试和 A/B 级 AI 味检查。

### 4.4 商务合作 / 求咨询 / 求转介绍

```
Subject: {一个对方有资格回答的领域问题，小写}

Hi {名},

{钩子：引对方某篇具体文章/帖子/发言，精确到主题}

{身份一行 + 我方一句话定位：我们在做的东西与对方工作的关系}

{一个来自对方位置的问题（"from your multi-client seat: ..."）——问信息，不问会面}

{可选给予：免费工具/数据/报告，主动声明无成本无条件}

{署名}
```
实测样本：C1 顾问触达模板（来源：`发现冲刺-20260919/发现冲刺工具包.md` ②）。
纪律：商务场景最容易滑向推销腔——第一封的请求永远是**信息**（对方视角的判断），不是会议、不是合作、不是转发。合作提案只在对方回复表达兴趣后才发。

## 5. 节奏与放弃纪律

### 5.1 间隔表（实测沉淀）

| 情形 | 规则 |
|---|---|
| 同一收件人重复触达 | **30 天内不收到第二封**（跨所有轨、所有 campaign 合并计算）（来源：expert-review-outreach 硬门） |
| 对方回复了 | **24 小时内**回（来源：`市场推广/GTM工作区/growth-ops/HANDOVER.md` 对话跟进纪律） |
| LinkedIn 邀请被接受 | 24 小时内发完整信；**7 天不接受=不打扰**，绝不发第二次邀请（撤回会触发 3 周锁定） |
| 首触未回 | 不发 "just bumping this" 式催促。7-14 天后可以**全新钩子/全新角度**作为一次"新首触"再进（来源：`newoutreach/INCIDENT-2026-08-22.md` 恢复计划对 C 低 fit 层的处置） |
| 已读不回 | 等同未回处理：不加急、不连发短消息、不换小号。能看见已读的渠道里，追一条"看到您已读"是灾难 |
| 明确拒绝/没空 | 记 plain reply，30 天内不再触达，不试图说服 |
| 几轮放弃 | 同一收件人累计 **2 次无回音**（含新角度重触）→ 移出活跃队列；此后只有出现强新钩子（对方的公开新动态与我方直接相关）才再进，否则永不 |
| 每日产能 | 深钩 ≤10 封（间隔 60-150s）；新渠道新触达 ≤5/日/渠道；LinkedIn 邀请 ≤8/日 |
| 熔断 | 单批退信率 >5% 立即停发复盘；连续 3 封发送失败停发查通道（来源：expert-review-outreach 发送纪律） |

### 5.2 "不打扰"也是正确决策

实测：一次事故后的恢复分层里，123 个低契合收件人被**主动选择不再打扰**，这一决策被复盘为正确而非损失。外联的目的是转化不是覆盖——对不该发的人不发，和对该发的人发好，同等重要（来源：`INCIDENT-2026-08-22.md` 恢复策略分层）。

### 5.3 发送通道附注（给自动化执行者）

Gmail Web UI 自动化已被实测否决：pre-send 校验无法证明真实发出的内容，449 封空正文事故即由此而来。可信通道只有 SMTP/API（正文是协议一部分，发送即验证）或人工发送。任何自动发送必须带：suppress 名单、退信熔断、发送后独立回读核验（来源：`INCIDENT-2026-08-22.md` 二次事故结论）。写邮件是本 skill 的职责；发送基础设施的安全规则在此只为防止绕过。

## 6. 输出合同

每封邮件的产出固定三件套，缺一即未完成：

### 第一件·研究摘要
- 收件人身份核实（当日）：姓名/头衔/公司/近况，来源链接
- 钩子列表：硬钩子（含出处链接）、处境/交集钩子
- 场景判定：冷触达 / 暖回访 / 求评（路由）/ 商务
- 渠道与节奏检查：冷却期（30 天）、suppress 名单、每日配额
- 钩子不合格 → 停在这里，不产出草稿

### 第二件·草稿
- Subject + 正文 + 署名
- 标注：词数（50-200）、问句数（恰 1，最多 2）、CTA 级别（L0-L4）
- 求评场景：标注"骨架来自 expert-review-outreach"

### 第三件·自检清单（三项全过才交稿）

**AI 味**
- [ ] 换名测试：换掉收件人后邮件不成立
- [ ] 无 A 级项（无锚点赞美 / 万能开头 / 元话语自证 / 空洞 CTA）
- [ ] 无 B 级项（无 bullet 排比 / 无 em dash / 无模板句式自指 / 礼貌不堆叠 / 问句数达标）
- [ ] 主题行像人写的（小写、具体、非营销腔）

**千人千面**
- [ ] 硬钩子 ≥1，2 分钟内可向第三方验证出处
- [ ] 当日核实过（对方头衔/公司/近况未过期）
- [ ] 与发给其他人的邮件无共享句式主干（正文不重复）

**结构**
- [ ] 顺序：钩子 → 拉距离 → 正事，无倒置
- [ ] 拉距离 ≤3 句、一句话定位、无 feature 列表
- [ ] 请求具体到物件/判断题，CTA 级别符合场景（首触 ≤L2）
- [ ] 署名完整：真名 + 身份行 + 链接
- [ ] 节奏合规：冷却期、配额、熔断已检查

任一项不过 → 回到研究或重写，不出"凑合版"。通用词表：[英文](./references/ai-tells-en.md) · [中文](./references/ai-tells-zh.md)；对照示例：[before-after.md](./references/before-after.md)；跟进与收口模板：[followup-templates.md](./references/followup-templates.md)。
