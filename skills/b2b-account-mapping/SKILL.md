# 公司账号辨别与换人触达（B2B Account Mapping）

## 何时使用

- 挖掘/登记新线索时（**进池前必做**，与钩子准入同级）
- 触达失败或无回应后（换人决策）
- 任何 B2B 外联批次编排前（确认每行都是"人"而非"账号"）

## 第一步：辨别账号性质

| 信号 | 个人账号 | 公司账号 |
|------|----------|----------|
| 付费主体 | 个人订阅（Pro / Pro+ / 个人信用卡） | 组织计划（Business / Enterprise / Teams / 平台合同 / 案例页客户） |
| 语言 | "I / my bill" | "we / our team / our org / our clients" |
| 资料归属 | 个人邮箱、个人站 | 公司域名邮箱、公司 GitHub org、公司头衔 |
| 痛感性质 | 个人预算痛 | 预算科目、合规、组织采购、续约谈判 |
| 典型例 | Copilot Pro 用户抱怨价格 | Copilot for Business 管理员抱怨预算不可见；Zendesk 案例页 logo |

判定优先级：**付费主体 > 语言 > 资料归属**。混合型（个人身份吐槽但代表组织，如"我已告诉办公室要迁移"）按付费主体归类，但该人可作"组织影响者"标签。

**硬规则：公司账号不能直接营销。** GitHub org、官方账户、案例页 logo、域名邮箱都是组织面具——触达必须落到具体员工。个人账号则不适用换人协议（无换人对象）。

## 第二步：公司账号富化到人

排序原则是**权责接近痛感**，不是职级高低：

| 跳序 | persona | 角色 | 价值 |
|------|---------|------|------|
| 1 | 运营负责人（CX Ops / Support Ops / 平台工程管理员） | 感知痛感、日常使用、内部倡导者 | 第一跳，回复率最高 |
| 2 | 职能预算持有人（VP / Director / Head） | 签字权 | 第一或第二跳 |
| 3 | 财务科负责人（CFO / VP Finance / Finance Manager） | owns 支出科目，最终追问数字 | 第二跳（A1 类）；A2 类与第一跳并重 |
| 4 | 执行者（Manager / 专员） | 信息源、多口证实 | 不作首触达，换人备选 |

部门权责映射（AgentMeasure 语境，其他项目按同理替换）：

- **CX / Support 部门**：owns resolution 口径与工单预算 → A1（per-resolution 客服）主 persona
- **Eng / 平台部门**：owns 工具采购、席位与限额配置 → A2（per-task / ACU）主 persona
- **Finance 部门**：owns AI 支出行项目与对账 → 二跳；若案例里出现财务头衔管 AI（如 Mercado Libre），升为 P0（两跳合一）
- **IT / 采购**：供应商管理与争议升级 → 换人备选方向

富化路径（只用公开来源）：厂商案例内页具名 quote → LinkedIn 公司页按头衔过滤 → 播客/网络研讨会嘉宾 → 新闻稿/转载媒体。JS 墙官网走预发布镜像或转载源。

## 第三步：换人协议（营销失败后继续）

**失败信号**（满足其一即计该人失败）：
- LinkedIn：邀请 7 天未接受（不追第二请求；撤回=3 周锁定，宁留 pending）
- 邮件：首发 + 7 天跟进共两封无回复
- 站内（GitHub/论坛）：无互动 14 天
- 明确拒绝或负面回复：立即停止该人，不换话术重试

**换人方向（按序）**：
1. 同部门平级（痛感相同，钩子微调即可）
2. 上级（VP/CXO，钩子换"金额与预算风险"话术）
3. 相邻部门（CX↔Finance、Eng↔Finance，钩子换对账口径话术）
4. 同公司其他已知具名人（案例页第二 quote 者）

**约束**：
- 每公司最多 3 轮换人；3 轮全败 → 公司进**冷却池**（90 天，或新事件/新钩子出现时提前解冻，如厂商调价、计费口径变更）
- 换人必换钩子视角：平级=原钩子微调；上级=金额风险；财务=对账；不复制粘贴原信
- 同一公司相邻触达间隔 ≥3 天（避免公司内撞车感）
- 个人账号不换人，最多两触点后冷却

## 第四步：记录格式（触达数据库）

每公司一个 account 块，人多行：

```
### 公司名（账号类型：公司）
- 厂商/计费单位：Zendesk / automated resolution
- 钩子来源：案例页 URL + 原话数字
- [1] 人名 | 头衔 | 部门 | persona跳序 | 渠道 | 状态
- [2] ...
- 换人历史：[1] failed(日期,原因) → [2] sent(日期)
- 池状态：active / cooled(日期)
```

状态枚举：`new → queued → sent → replied → qualified(给量级/约通话) / failed(原因) → 换人 or cooled`。

## 红线

- 只用公开来源富化；不买名单、不绕登录墙、不碰凭据
- 换人是"换视角重新介绍"，不是同信轰炸——每一轮都要能通过"这个人为什么现在该听"的自检
- 钩子准入不变：每个新触达对象仍必须有公开数字/公开引用钩子
