# deck 模式：信息密度高、结合图表、符合演示场景

普通 deck、管理层方案和经营汇报都用本文件；管理层特有的纪律见「管理层与经营汇报」一节。业务型 BP、多产品族方案另加读[业务 BP 方法](bp-business.md)；面向投资人的融资 BP 另读 [bp-deck.md](bp-deck.md)。

## 第一性原理

听众只有两种状态——**抬头扫一眼页面，或低头听你说话**。所有规则从这两个状态倒推：

- **扫**：5 秒内抓住这一页的主张
- **讲**：每句文案能直接从嘴里说出来，不绊嘴

信息密度高 ≠ 往页面上堆字，是**每个字都干活**：删承接词（页面顺序已经承担逻辑）、动词开头数字收尾、留白给重点。信息密度低的 deck 通常不是字少，是字多但没主张。

## 一、页面文案

### 页标题

1. **写结论，不写主题**。「市场分析」「产品概述」等于没说；把这一页的主张直接放进标题。判据：全 deck 标题单独抽出来连读，能复述出整份 deck 的论证线
2. **一句一断言**：「更低的价格，更好的体验」是两个断言凑对仗，砍一半留更狠的
3. **长度**：以现场可读为准，中文主标题尽量收在约 16 字内；超长时检查是否还在描述背景而没有说出判断。eyebrow / kicker 不计
4. **含动词或判断词**：「XX 能力的构建与探索」是名词堆，还原成动作
5. 页标题避免纯修辞的二元对比、口号词（重新定义 / 新纪元 / 引领未来）和空泛比较级排比；对比确实承担决策信息时可以保留

### 正文要点

1. **一页一观点**。所有要点服务于标题的断言；一页出现两组不相干的要点是拆页信号（提出，不擅自重组）
2. **信息容量**：一组要点通常不超过 5 条，单条尽量能在两行内读完。页面拥挤时先删重复、拆复杂关系，别只靠缩字号；技术附录和数据表可按真实阅读需要例外
3. **动词开头，数字收尾**：「强大的性能」→「冷启动 1.2 秒」。同组要点保持同一语法形状，但不强行凑三条
4. **量级具体化**：「很多用户」→「月活 82,178」；没数据写`【待填】`，不写无源最高级
5. 删承接词：要点里不出现「首先 / 其次 / 此外」——听众扫的是形状，不是连接词

### 讲者备注

- 备注是说话不是念稿，允许口语和不完整句；「本页将阐述……」删掉，第一句直接进内容
- **不复读页面**。讲三件 slide 上放不下的：这页为什么存在（解决听众哪个疑问）、从上页怎么过渡、放不下的细节和数字出处
- **预埋问答**：写清这页最可能被追问的一件事和回答方向（「如果被问到 X，往 Y 答」）
- 每页 80–200 字，够讲 30–60 秒

### 定位与业务段落（lede / 结论条 / 市场描述）

- **业务方直读测试**：读完一段，不懂技术的业务方能复述出「谁对谁做什么、怎么赚钱、凭什么成立」
- 翻译腔清洗、名词化还原，同通用底线 1.1
- 每页允许一句有辨识度的定位句，但不得每页同款句式收尾
- 普通 deck 不套融资叙事

## 二、图表（能画图就不写字）

这是 deck 和其他文体的分水岭：**数字对比、趋势、构成、流程，优先用图，不用 bullet 硬描述**。

### 选型

| 要表达 | 用什么 | 注意 |
| --- | --- | --- |
| 数值对比（A vs B、多方案） | 柱状 / 条形 | 类别多时用条形（标签横排好读） |
| 趋势、随时间变化 | 折线 | 一条线一个变量，超 4 条拆图 |
| 构成占比 | 堆叠柱 / 环形 | 类别多时可归成「其他」，但不能掩盖重要差异 |
| 流程、链路 | 流程图 | 步骤 ≤ 7，超过就分层 |
| 结构、关系 | 架构图 | 框 ≤ 9 个，箭头方向 = 数据/资金/控制流方向 |
| 时间线、里程碑 | timeline | 现在所在位置要标出来 |
| 精确对照（参数/价格/竞品） | 表格 | 表格不是图，别当段落写；列 ≤ 5 |

### 图表三要素

1. **结论式图题**：「复购率随持有时长上升」，不是「复购率数据」。图题就是这一页的标题候选
2. **轴标签带单位**，图例齐全，数据时间范围写清
3. **来源行**：图下来源标注（「来源：公司后台 2026Q3」）。没有真实数据就整图标`【待填】`，不画示意性假数据

### 图文分工

- 一页一图为主；图和文字**不重复说同一件事**——文字给图的解读和 so what（「图上这个拐点对应我们切换渠道的那个月」）
- 图里的数字不在正文要点里重抄一遍，指向它：「右图拐点」
- 需要标注的关键点 ≤ 2 个/图（圈、箭头、高亮），全标等于没标

## 三、管理层与经营汇报

经用户认可的实践（2026-11-10 高尔夫 v11、2026-11-17 OVO BP v7 两次确认）。在上述规则之上，管理层 deck 另有这些纪律：

### 读者与结构

- **为老板和业务人员写**。首页正式封面；正文标题直接给判断，一页回答一个完整经营问题。
- **信息密度靠整合关系**：市场对比与进入理由同页，功能与证据/验证同页，费用与组成/边界同页。避免每个小要点各占一页，也不把文字缩小硬塞。
- 先组织完整问题，再决定页数；不套固定页数模板。
- 在用户确认的原材料上增量修改，保留统一入口和版本基线；先复核研究，再组织页面。

### 经营内容口径

- 里程碑围绕产品设计 → 工程样机 → 试产 → 小批交付 → 量产交付。Demo 不是 EVT 验收，试产不等于大规模量产能力。
- 团队页回答「谁、什么资历、做什么、何时加入」，区分相邻岗位（如项目经理与产品经理）。岗位级别是招聘目标，不按年限虚构现有人选资历。
- 财务页保留分母、计费边界和假设。费用按真实构成拆分（平台、支付、固定服务费、归因佣金、广告与履约）。保本标明是活动保本还是项目回本；固定推算不能当成随销量不变的事实。
- 图中必须有单位和假设；没有证据不画排名分数、市场占比或预测趋势。

### 视觉起点（复用起点，非硬参数）

1600×900 横版，奶油白底配深森林绿，低饱和绿与金区分图表；深色封面与浅色正文形成层次。正文标题约 43px，内容 18–22px，来源 14px。页面常用「结论标题＋一句口径＋左右信息区＋必要的行动条＋来源」；整份稿有节奏——对比矩阵、证据表、流程图、条形图、瀑布图穿插，不把每页做成同款卡片。封面允许留白，正文优先完整表达决策关系。

### 实施工具与核验

- 版面从零搭建或重排时加载 `deck-design`（12 列网格、python-pptx 骨架、图表配方、逐页渲染与几何审计）；需要维护预算输入与公式时用表格工具联动。没有使用的技能不得列作来源。
- 同一数字从一个来源读取；重算后同步相关页面（如人数变化带动的办公、设备、外包扣减）。
- 逐页渲染检查正文与页脚重叠、表格截断、页面数和本地链接。预算勾稽只证明算术正确，不证明商业假设成立。
- 告知改了什么及重要预算影响；不把生成脚本和过程文件作为管理层材料交付。

## 四、与其他 deck skill 的分工

- **本文件**：从零写 deck 文案、常规打磨、图文规划——说什么、证据和口径对不对
- **deck-design**：PPTX 版面层——从零搭或重排 16:9 deck，python-pptx 骨架、网格版面系统、图表配方、逐页渲染与几何审计。要产出真 PPTX 或做版式重排时加载它
- **presentations:pptx**（官方插件）：文件层——读取/抽取已有 .pptx（markitdown）、编辑重排、转 PDF、渲染逐页 PNG 预览；没有 deck-design 的环境里也从零创建。做业务 deck 时版面优先 deck-design，文件操作用本插件
- **impeccable**：HTML deck 与配套网页的视觉层——可编辑 HTML 演示稿（如管理层 v11 式交付）、产品站、着陆页的视觉与交互设计。HTML 形态的 deck 加载它；页文案与证据口径仍归本文件
- **deck-humanizer**：已有 deck 的专项去 AI 味深度改写（四子场景细则、Tier 词表、静态检查脚本 `check_deck_copy.py`、JSON/Python 数据源的等结构输出）。用户要求「deck 去AI味」且文案量大时，加载它执行

冲突时，文案与证据规则优先于视觉偏好。

## 五、deck 检查清单

**AI 味与机翻**
- [ ] 标题全是结论式；抽出来连读能复述论证线
- [ ] 机械二元对比、无证据金句和空话已清；必要的真实对比仍在
- [ ] 中英夹杂直译已改中文；行业缩写白名单除外
- [ ] 念一遍最长的句子——绊嘴的都拆短

**演示场景**
- [ ] 页面主张清楚；要点能扫读，复杂信息没有被缩小字号硬塞
- [ ] 要点动词开头、数字收尾；量级具体化或`【待填】`
- [ ] 该用图的地方没用 bullet 硬写；图题是结论；有单位和来源
- [ ] 讲者备注不复读页面、含过渡和预埋问答
- [ ] 数据都带来源；没数据的是`【待填】`不是编的
- [ ] 全 deck 读完，业务方能复述「做什么、怎么赚钱、凭什么成立」

**管理层另查**
- [ ] 同一数字全稿一个来源；重算后相关页面已同步
- [ ] 里程碑、保本口径、岗位资历没有夸大；过程文件未混入交付
