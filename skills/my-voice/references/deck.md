# deck 模式：信息密度高、结合图表、符合演示场景

## 第一性原理

听众只有两种状态——**抬头扫一眼页面，或低头听你说话**。所有规则从这两个状态倒推：

- **扫**：5 秒内抓住这一页的主张
- **讲**：每句文案能直接从嘴里说出来，不绊嘴

信息密度高 ≠ 往页面上堆字，是**每个字都干活**：删承接词（页面顺序已经承担逻辑）、动词开头数字收尾、留白给重点。信息密度低的 deck 通常不是字少，是字多但没主张。

## 一、页面文案

### 页标题

1. **写结论，不写主题**。「市场分析」「产品概述」等于没说；把这一页的主张直接放进标题。判据：全 deck 标题单独抽出来连读，能复述出整份 deck 的论证线
2. **一句一断言**：「更低的价格，更好的体验」是两个断言凑对仗，砍一半留更狠的
3. **长度**：以现场可读为准，中文主标题尽量收在约 16 字内；超长时检查是否还在描述背景而没有说出判断。eyebrow / kicker 不计
4. **含动词或判断词**：「XX 能力的构建与探索」是名词堆，还原成动作
5. 页标题避免纯修辞的二元对比、口号词（重新定义 / 新纪元 / 引领未来）和空泛比较级排比；对比确实承担决策信息时可以保留

### 正文要点

1. **一页一观点**。所有要点服务于标题的断言；一页出现两组不相干的要点是拆页信号（提出，不擅自重组）
2. **信息容量**：一组要点通常不超过 5 条，单条尽量能在两行内读完。页面拥挤时先删重复、拆复杂关系，别只靠缩字号；技术附录和数据表可按真实阅读需要例外
3. **动词开头，数字收尾**：「强大的性能」→「冷启动 1.2 秒」。同组要点保持同一语法形状，但不强行凑三条
4. **量级具体化**：「很多用户」→「月活 82,178」；没数据写`【待填】`，不写无源最高级
5. 删承接词：要点里不出现「首先 / 其次 / 此外」——听众扫的是形状，不是连接词

### 讲者备注

- 备注是说话不是念稿，允许口语和不完整句；「本页将阐述……」删掉，第一句直接进内容
- **不复读页面**。讲三件 slide 上放不下的：这页为什么存在（解决听众哪个疑问）、从上页怎么过渡、放不下的细节和数字出处
- **预埋问答**：写清这页最可能被追问的一件事和回答方向（「如果被问到 X，往 Y 答」）
- 每页 80–200 字，够讲 30–60 秒

### BP 段落（lede / 结论条 / 定位段 / 市场描述）

- **业务方直读测试**：读完一段，不懂技术的业务方能复述出「谁对谁做什么、怎么赚钱、凭什么成立」
- 翻译腔清洗、名词化还原，同通用底线 1.1
- 每页允许一句有辨识度的定位句，但不得每页同款句式收尾

## 二、图表（能画图就不写字）

这是 deck 和其他文体的分水岭：**数字对比、趋势、构成、流程，优先用图，不用 bullet 硬描述**。

### 选型

| 要表达 | 用什么 | 注意 |
| --- | --- | --- |
| 数值对比（A vs B、多方案） | 柱状 / 条形 | 类别多时用条形（标签横排好读） |
| 趋势、随时间变化 | 折线 | 一条线一个变量，超 4 条拆图 |
| 构成占比 | 堆叠柱 / 环形 | 类别多时可归成「其他」，但不能掩盖重要差异 |
| 流程、链路 | 流程图 | 步骤 ≤ 7，超过就分层 |
| 结构、关系 | 架构图 | 框 ≤ 9 个，箭头方向 = 数据/资金/控制流方向 |
| 时间线、里程碑 | timeline | 现在所在位置要标出来 |
| 精确对照（参数/价格/竞品） | 表格 | 表格不是图，别当段落写；列 ≤ 5 |

### 图表三要素

1. **结论式图题**：「复购率随持有时长上升」，不是「复购率数据」。图题就是这一页的标题候选
2. **轴标签带单位**，图例齐全，数据时间范围写清
3. **来源行**：图下来源标注（「来源：公司后台 2026Q3」）。没有真实数据就整图标`【待填】`，不画示意性假数据

### 图文分工

- 一页一图为主；图和文字**不重复说同一件事**——文字给图的解读和 so what（「图上这个拐点对应我们切换渠道的那个月」）
- 图里的数字不在正文要点里重抄一遍，指向它：「右图拐点」
- 需要标注的关键点 ≤ 2 个/图（圈、箭头、高亮），全标等于没标

## 三、与 deck-humanizer 的分工

- **本文件**：从零写 deck 文案、常规打磨、图文规划
- **deck-humanizer**：已有 deck 的专项去 AI 味深度改写（四子场景细则、Tier 词表、静态检查脚本 `check_deck_copy.py`、JSON/Python 数据源的等结构输出）。用户要求「deck 去AI味」且文案量大时，加载它执行

## 四、deck 检查清单

**AI 味与机翻**
- [ ] 标题全是结论式；抽出来连读能复述论证线
- [ ] 机械二元对比、无证据金句和空话已清；必要的真实对比仍在
- [ ] 中英夹杂直译已改中文；行业缩写白名单除外
- [ ] 念一遍最长的句子——绊嘴的都拆短

**演示场景**
- [ ] 页面主张清楚；要点能扫读，复杂信息没有被缩小字号硬塞
- [ ] 要点动词开头、数字收尾；量级具体化或`【待填】`
- [ ] 该用图的地方没用 bullet 硬写；图题是结论；有单位和来源
- [ ] 讲者备注不复读页面、含过渡和预埋问答
- [ ] 数据都带来源；没数据的是`【待填】`不是编的
- [ ] 全 deck 读完，业务方能复述「做什么、怎么赚钱、凭什么成立」
