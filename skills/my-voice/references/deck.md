# deck 模式：信息密度高、结合图表、符合演示场景

普通 deck、管理层方案和经营汇报都用本文件；管理层特有的纪律见「管理层与经营汇报」一节。业务型 BP、多产品族方案另加读[业务 BP 方法](bp-business.md)；面向投资人的融资 BP 另读 [bp-deck.md](bp-deck.md)。

## 第一性原理

听众只有两种状态——**抬头扫一眼页面，或低头听你说话**。所有规则从这两个状态倒推：

- **扫**：5 秒内抓住这一页的主张
- **讲**：每句文案能直接从嘴里说出来，不绊嘴

信息密度高 ≠ 往页面上堆字，是**每个信息元素都在证明同一个主张**：删承接词（页面顺序已经承担逻辑）、动词开头数字收尾、留白给重点。信息密度低的 deck 通常不是字少，是字多但没主张，或多张图各说一件事。

## 一、先写页级内容合同

每页在写文案或打开 PPT 工具前，先填这张合同。只有封面、分节页和纯视觉过渡页可以简化。

| 字段 | 必须写清什么 |
| --- | --- |
| `audience_question` | 读者看完这页要回答哪个问题？融资页写投资问题，经营页写决策问题 |
| `assertion` | 唯一主张；标题是它的短句表达，不是主题名 |
| `evidence_role` | 本页证明需求、机制、traction、市场、团队、财务还是其他什么 |
| `primary_visual` | 主图的图型、数据、单位、时间、分母、来源、标注；没有数据就不画假图 |
| `supporting_modules` | 1–2 个支撑模块：比较、客户原话、产品流程、公式、基准、反例或下一验证 |
| `takeaway` | 读者应带走的业务含义或决策，不重复抄图中数字 |
| `sources_and_caveat` | 来源、实际/推算/目标、最重要的一个限制；完整限制进备注或附录 |
| `speaker_note` | 过渡、解释和最可能追问，不复读页面 |
| `content_status` | `已核实 / 待补证 / 假设模型 / 示例`，示例和假设不得混入实际业绩 |

**页面完成判据**：只读标题能知道主张；只看主图能知道关键证据；看辅助模块能理解比较、机制或意义；看来源能复核；标题连读能复述整份 deck。

### 信息密度的六个有效元素

丰富度从这些元素中选择，而不是增加装饰：

1. **主张**：一个判断，不凑对仗。
2. **主证据**：一张主图、产品演示或关键流程，承担主要证明。
3. **比较基准**：过去、替代方案、目标客户、同口径 cohort 或明确假设。
4. **解释与含义**：为什么发生、对业务/产品/融资决定意味着什么。
5. **边界与反例**：最重要的样本限制、反例或未知；只说一次。
6. **下一动作**：下一验证、决策或里程碑；不是每页都需要，但早期证据页通常要有。

客户原话、公式、产品局部截图、注释、数据表和里程碑都可以成为有效内容元素；库存图片、渐变背景、图标墙、重复 KPI 和无信息口号不算丰富度。

### 按交付形态分配密度

| 形态 | 页面层级 | 密度原则 |
| --- | --- | --- |
| `live pitch` 现场路演 | 结论标题 + 一个主图/演示 + 必要口径；解释进口播 | 大字、单点、立即看懂；不要把转发版缩字后投屏 |
| `forwardable` 可转发阅读 | 结论标题 + 主图 + 1–2 个支撑模块 + so-what + 来源 | 不在场也能读懂论证；可增加证据层，不增加第二个主张 |
| `management` 管理层/经营汇报 | 结论 + 决策相关证据 + 方案/费用/边界 + 行动 | 围绕完整经营问题整合关系，不把每个小要点拆成一页 |
| `appendix/data room` 附录与尽调 | 精确表格、定义、公式、完整 cohort、财务假设 | 以可复核为目标，可以密，但不能乱、不能无单位、不能截断 |

**密度不足时先补证据和关系，不补形容词。** 一页只有三个 KPI 时，检查是否缺比较基准、原因解释、客户行为或下一验证；一页有三张图时，检查它们是否其实在回答三个不同问题。需要缩到设计 skill 的字号下限以下才能放下时，删重复、换图或拆页。

## 二、页面文案

### 页标题

1. **写结论，不写主题**。「市场分析」「产品概述」等于没说；把这一页的主张直接放进标题。判据：全 deck 标题单独抽出来连读，能复述出整份 deck 的论证线
2. **一句一断言**：「更低的价格，更好的体验」是两个断言凑对仗，砍一半留更狠的
3. **长度**：以现场可读为准，中文主标题尽量收在约 16 字内；超长时检查是否还在描述背景而没有说出判断。eyebrow / kicker 不计
4. **含动词或判断词**：「XX 能力的构建与探索」是名词堆，还原成动作
5. 页标题避免纯修辞的二元对比、口号词（重新定义 / 新纪元 / 引领未来）和空泛比较级排比；对比确实承担决策信息时可以保留
6. **不用抽象 umbrella 标题盖住多组证据。**「采用加深 / 价值显现 / 潜力释放」没有说明发生了什么；改成具体关系，如「活跃和付费团队连续两月一起增长」。必须并列两个独立结果才能说清时，聚焦最强一个或拆页

### 正文要点

1. **一页一观点**。所有要点服务于标题的断言；一页出现两组不相干的要点是拆页信号（提出，不擅自重组）
2. **信息容量**：一组要点通常不超过 5 条，单条尽量能在两行内读完。页面拥挤时先删重复、拆复杂关系，别只靠缩字号；技术附录和数据表可按真实阅读需要例外
3. **动词开头，数字收尾**：「强大的性能」→「冷启动 1.2 秒」。同组要点保持同一语法形状，但不强行凑三条
4. **量级具体化**：「很多用户」→「月活 82,178」；没数据写`【待填】`，不写无源最高级
5. 删承接词：要点里不出现「首先 / 其次 / 此外」——听众扫的是形状，不是连接词

### 讲者备注

- 备注是说话不是念稿，允许口语和不完整句；「本页将阐述……」删掉，第一句直接进内容
- **不复读页面**。讲三件 slide 上放不下的：这页为什么存在（解决听众哪个疑问）、从上页怎么过渡、放不下的细节和数字出处
- **预埋问答**：写清这页最可能被追问的一件事和回答方向（「如果被问到 X，往 Y 答」）
- 每页 80–200 字，够讲 30–60 秒

### 定位与业务段落（lede / 结论条 / 市场描述）

- **业务方直读测试**：读完一段，不懂技术的业务方能复述出「谁对谁做什么、怎么赚钱、凭什么成立」
- 翻译腔清洗、名词化还原和中英文业务表达见 [business-language.md](business-language.md)
- 每页允许一句有辨识度的定位句，但不得每页同款句式收尾
- 普通 deck 不套融资叙事

## 三、图表（能画图就不写字）

这是 deck 和其他文体的分水岭：**数字对比、趋势、构成、流程，优先用图，不用 bullet 硬描述**。

### 选型

| 要表达 | 用什么 | 注意 |
| --- | --- | --- |
| 数值对比（A vs B、多方案） | 柱状 / 条形 | 类别多时用条形（标签横排好读） |
| 趋势、随时间变化 | 折线 | 一条线一个变量，超 4 条拆图 |
| 构成占比 | 堆叠柱 / 环形 | 类别多时可归成「其他」，但不能掩盖重要差异 |
| 流程、链路 | 流程图 | 步骤 ≤ 7，超过就分层 |
| 结构、关系 | 架构图 | 框 ≤ 9 个，箭头方向 = 数据/资金/控制流方向 |
| 时间线、里程碑 | timeline | 现在所在位置要标出来 |
| 精确对照（参数/价格/竞品） | 表格 | 表格不是图，别当段落写；列 ≤ 5 |

### 图表三要素

1. **结论式图题**：「复购率随持有时长上升」，不是「复购率数据」。图题就是这一页的标题候选
2. **轴标签带单位**，图例齐全，数据时间范围写清
3. **来源行**：图下来源标注（「来源：公司后台 2026Q3」）与必要样本口径，不写和本页无关的“无市场/竞品数据”等缺失清单。没有真实数据就整图标`【待填】`，不画示意性假数据

### 数据与比较口径

每张图的数据源至少保留 `series / unit / time window / denominator / source / actual-derived-target / formula`。页面上的百分比、文字和讲者备注从同一数据源生成。

- **同期、同单位、同分母、同定义才直接比较。** 当周快照、月度序列、累计值、cohort 不放在同一轴上；不能比较时换口径、分区或另页，不靠长解释救图。
- **绝对值与比例一起给。** 小基数百分比不能单独证明增长；比例可能四舍五入时，不反推精确人数。
- **实际、推算、目标视觉可分。** 实际用实线/实心，目标和假设用虚线/浅色并直接标字，不仅靠图例猜。
- **默认不用双轴、截轴和累计曲线证明增长。** 期间数据优先；确需累计图时同时给期间增量。
- **派生数字带公式与近似程度。** 图表、正文和备注中的值必须能相互复算。
- **截图先简化再标注。** 产品截图只保留能证明主张的局部与步骤，小字界面全截图不算产品演示。

### 融资与业务页的图表升级

| 页面任务 | 更好的表达 | 避免 |
| --- | --- | --- |
| 增长 | 期间收入/活跃/付费的绝对值 + 同口径增速；标注关键动作 | 只画累计注册、只写增长率 |
| 留存 | cohort 曲线/表，带起始分母、时间窗和样本限制 | 把 4/9 叫长期留存；不说明 W4/W8 |
| 客户价值 | 前后流程 + 时间/成本/质量指标 + 样本来源 | 只有“效率提升”或假精确 ROI |
| 商业模式 | 谁付、付什么、费率、交付成本；单位经济瀑布或收入桥 | GMV 当收入、实施费塞 ARR |
| 市场 | 客户数 × 年支出的可复算树/表 + wedge 扩张路径 | 三层同心圆只有大数、行业总产值乘份额 |
| GTM | 同时间窗的真实漏斗 + 渠道动作 + 转化率分母 | 无数量的营销漏斗、只写“渠道合作” |
| 竞争 | 客户选择标准 × 替代方案；有依据才用 2×2 | logo 墙、雷达图全满分、凭空排名 |
| 融资用途 | 资金/资源 → 里程碑 → 下一证据的对应表 | 无依据预算 donut、随意中间目标折线 |

### 图文分工

- 一页一个**主图**；可转发版可再加 1–2 个辅助模块，但它们必须证明同一主张，不把多张完整小图拼成仪表盘。
- 图和文字**不重复说同一件事**——文字给图的解读和 so what（「图上这个拐点对应我们切换渠道的那个月」）
- 图里的数字不在正文要点里重抄一遍，指向它：「右图拐点」；关键口径和分母不属于重复，必须保留。
- 需要标注的关键点 ≤ 2 个/图（圈、箭头、高亮），全标等于没标

## 四、管理层与经营汇报

经用户认可的实践（2026-11-10 高尔夫 v11、2026-11-17 OVO BP v7 两次确认）。在上述规则之上，管理层 deck 另有这些纪律：

### 读者与结构

- **为老板和业务人员写**。首页正式封面；正文标题直接给判断，一页回答一个完整经营问题。
- **信息密度靠整合关系**：市场对比与进入理由同页，功能与证据/验证同页，费用与组成/边界同页。避免每个小要点各占一页，也不把文字缩小硬塞。
- 先组织完整问题，再决定页数；不套固定页数模板。
- 在用户确认的原材料上增量修改，保留统一入口和版本基线；先复核研究，再组织页面。

### 经营内容口径

- 里程碑围绕产品设计 → 工程样机 → 试产 → 小批交付 → 量产交付。Demo 不是 EVT 验收，试产不等于大规模量产能力。
- 团队页回答「谁、什么资历、做什么、何时加入」，区分相邻岗位（如项目经理与产品经理）。岗位级别是招聘目标，不按年限虚构现有人选资历。
- 财务页保留分母、计费边界和假设。费用按真实构成拆分（平台、支付、固定服务费、归因佣金、广告与履约）。保本标明是活动保本还是项目回本；固定推算不能当成随销量不变的事实。
- 图中必须有单位和假设；没有证据不画排名分数、市场占比或预测趋势。

### 视觉起点（复用起点，非硬参数）

1600×900 横版，奶油白底配深森林绿，低饱和绿与金区分图表；深色封面与浅色正文形成层次。正文标题约 43px，内容 18–22px，来源 14px。页面常用「结论标题＋一句口径＋左右信息区＋必要的行动条＋来源」；整份稿有节奏——对比矩阵、证据表、流程图、条形图、瀑布图穿插，不把每页做成同款卡片。封面允许留白，正文优先完整表达决策关系。

### 实施工具与核验

- 版面从零搭建或重排时加载 `deck-design`（12 列网格、主题/模板与组件契约、图表配方）；生成与导出按 [deck-production.md](deck-production.md)，存量或高度定制原生图表才用 python-pptx。需要维护预算输入与公式时用表格工具联动。没有使用的技能不得列作来源。
- 同一数字从一个来源读取；重算后同步相关页面（如人数变化带动的办公、设备、外包扣减）。
- 实际 PPTX/PDF 成品逐页渲染检查正文与页脚重叠、表格截断、页面数和本地链接，不用源浏览器预览代替。预算勾稽只证明算术正确，不证明商业假设成立。
- 告知改了什么及重要预算影响；不把生成脚本和过程文件作为管理层材料交付。

## 五、与其他 deck skill 的分工与生产顺序

- **本文件 + `my-voice`**：从零写 deck、常规打磨、投资/经营叙事、页级内容合同、图文规划和中英文表达——说什么、证据和口径对不对。
- **`deck-design`**：设计决策层——网格、主题、字体、页型、组件、图表配方与视觉 QA。实际 PPTX 或版式重排时必须加载；在 my-voice 工作流中输出主题/模板和组件契约，不为新代码型 Deck 默认启动旧 python-pptx 管线。
- **[`deck-production.md`](deck-production.md)**：生成路由正本——新代码型 Deck 默认 Slidev，GUI/可编辑交付优先 Presenton，Marp 仅作轻量备选，python-pptx 留给存量与高度定制原生图表。图片型与可编辑 PPTX 的边界、导出命令和官方来源见该文件。
- **`pptx-deck-toolkit`**：审计层——环境里存在时对实际 PPTX 做内容契约与 C1–C10 检查；它只审计，不代替成品渲染。
- **`presentations:pptx`**（官方插件）：文件层——按环境读取/抽取已有 `.pptx`、编辑、转 PDF、渲染逐页 PNG。没有该插件时明说实际可用的替代工具，不假装调用。
- **`deck-scaffold` / `impeccable`**：前者只维护存量项目，不用于新 Deck；后者只在独立高交互网页或特殊 HTML 展示时按需使用，均不作为默认 PPT 生产器。
- **`deck-humanizer`**：已有 deck 的专项去 AI 味、术语保护和静态文案检查。它在叙事与证据完成之后工作，不自行缩掉必要事实，也不代替设计。
- **`shuorenhua`**：长文和通用中英文去味；批量 deck 仍优先 `deck-humanizer`。

### 实际生产顺序

1. **`content-lock`**：用页级内容合同锁定目标读者、整份主线、逐页问题/主张/事实/图表/来源/限制。改内容先改这里。
2. **语言锁**：按 `business-language.md` 完成中英文表达；已有大量文案时调用 `deck-humanizer`，保留数据、术语、来源和待补位。
3. **`visual-lock`**：由 `deck-design` 定义主题、网格、字体、色彩、组件、图表样式和导出目标。视觉不能反过来改变事实和证据强度。
4. **成熟工具生成**：用 Slidev 或 Presenton 生成、编辑和导出；存量/高度定制原生图表才走 python-pptx。图片型 PPTX 和可编辑 PPTX 必须如实区分。
5. **两道核验与回读**：先对实际 PPTX 做内容/几何审计，再把实际成品渲染为 PNG，看 contact sheet 和关键页原尺寸；最后重新打开 PPTX/PDF 核对页数、备注、图表值、可编辑性、字体和链接。源浏览器预览不能代替成品复核。
6. **交付**：按用户要求给实际 PPTX/PDF/HTML 与讲稿；构建脚本、审计日志和逐页截图留在内部，不冒充管理层交付。

冲突优先级：**事实与来源 > 投资/经营主线 > 读者理解 > 视觉偏好 > 机械行数或页数限制。** 任何工具不可用都要报告未完成的核验，不把“代码生成成功”或“源页面预览正常”当成“PPT 已验收”。

## 六、deck 检查清单

**主张与信息密度**
- [ ] 每页内容合同完整；标题全是结论式，抽出来连读能复述论证线
- [ ] 一页一个主张、一个主图；辅助模块提供比较、机制、含义或下一验证，不另起主张
- [ ] 路演、转发、经营和附录密度适配场景；没有靠低于字号下限硬塞
- [ ] 页面有有效证据和业务含义，不是只有 KPI、形容词、库存图或装饰

**数据与图表**
