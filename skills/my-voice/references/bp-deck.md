# 融资 BP deck：先立投资论点，再用证据降低不确定性

只用于面向投资人的融资 BP、路演和创始人 pitch。页面合同、图表和中英文表达继承 [deck.md](deck.md) 与 [business-language.md](business-language.md)；公开方法和案例证据见 [bp-investor-research.md](bp-investor-research.md)。

融资 BP 不是把公司资料填满固定栏目，而是让投资人逐步相信：**这个机会值得承担风险，这支团队有能力把它做成，这笔钱能把关键不确定性变成下一阶段证据。** PPT 帮助表达，不被写成融资成功的单一原因。

## 一、先做四张底表，再写页序

### 1. 场景卡

开始前尽可能确认：

- 融资阶段、基金类型、投资人类型与已知偏好。
- `live pitch` 现场口播、`forwardable` 可转发阅读、`partner meeting` 会谈还是 `data room` 尽调材料。
- 当前产品、真实 traction、最大不确定性、拟融资金额和下一里程碑。
- 中文、英文或双语；哪些材料可对外，哪些只能进内部数据室。

缺信息时先用已知事实组织可讲版本，把关键空缺集中列出；不要编数字、创始人经历、客户反馈或基金偏好。

### 2. 事实账本

每个核心数字记录：`值 / 单位 / 时间窗口 / 分母 / 来源 / 实际或推算 / 负责人 / 可公开性`。另标 `实际发生 / 内部推算 / 客户自述 / 第三方数据 / 示例 / 未来目标`。

派生值保留原始精度与公式。比例可能四舍五入时不反推精确人数；当周某日快照、月度序列、累计值和 cohort 不混算。MRR 年化运行率不是已实现年度收入，意向书不是 bookings 或 revenue。

### 3. 投资论点表

写 3–5 句“投资人成为股东必须相信的事”，每句配一项最能提高置信度的证据和一个最大反证：

| 必须相信 | 当前最强证据 | 最大反证/未知 | 下一验证 |
| --- | --- | --- | --- |
| 例：某类财务团队愿意持续为异常处理付费 | 真实付费、连续使用、续费 | 样本小、其他团队状态未知 | 扩大付费样本并追踪续费 |

投资论点不是`市场很大 / 产品很强 / 团队优秀`三句口号。首屏或前两页让公司定义和最强论点可被复述，后续页面逐项证明；不必另做一张写满抽象信念的“投资论点页”。

### 4. 异议表

列出最可能阻止本轮投资的 1–3 个问题：需求不够痛、市场不够大、收入模式不成立、竞争太挤、技术不可行、团队缺关键能力、数据太早、渠道不可复制、估值与阶段不匹配。把最大异议前置到有证据回应的位置，不藏到附录。

## 二、先选叙事类型，再排证据顺序

| 当前状态 | 叙事方式 | 先放什么 | 必须坦白什么 |
| --- | --- | --- | --- |
| 数据已经强 | **data-driven**：用经营与客户行为证明增长、留存、收入质量或资本效率 | 最强 traction、收入/使用质量、 cohort、单位经济 | 数据口径、异常月份、不可复制部分 |
| 数据仍弱但概念与团队强 | **concept-driven**：解释未来为何出现、凭什么是我们、怎样到达 | 独特洞察、why now、产品机制、创始人匹配、下一验证 | 尚未证明的关键假设，不伪装成 data pitch |
| 技术风险最高 | **技术验证驱动**：先降低“做不出来/不可靠”的疑问 | 原型、基准、可靠性、边界、失败与修正 | 评测范围、对照组和不能做什么 |
| 市场 crowded | **替代方案驱动**：先解释客户为何切换 | 现有替代、选择标准、具体差异、迁移成本 | 竞品强势与自身未验证项 |
| 商业化是最大异议 | **收入引擎驱动**：先回答谁付、为何付、如何续 | 实际价格、付费行为、毛利/交付成本、续费 | 意向与收入、GMV 与收入、一次性与 recurring |

没有扎实 traction 不等于不能写；它意味着不能把愿景写成经营结果。类比可以帮助理解，但不能替代需求、市场与单位经济推理。

## 三、页面按证明责任组织，不套固定页序

以下是证明责任清单，不是必须照抄的 10 页模板。每页只回答一个主要投资问题；同一主题需要多页时就拆，材料撑不起一页时就合并或标缺口。强 traction、技术风险或最大异议可以改变顺序。

| 页面角色 | 要回答的问题 | 主体内容与推荐图型 | 常见失误 |
| --- | --- | --- | --- |
| 公司定义 / 投资摘要 | 一句话能否说清是谁、为谁、做什么、为何值得继续看？ | 一句 declarative sentence + 最强证据 + 当前融资目标；不必堆 5 个 KPI | `AI platform for X`、愿景代替当前产品、首屏即整页免责声明 |
| 问题与现有替代 | 谁在什么任务上付出什么代价，现在怎么解决？ | 客户 workflow、替代成本、预算/决策人；前后流程或成本条 | 泛行业痛点、访谈兴趣当付费、没有买家 |
| 独特洞察 / Why now | 哪个旧约束变了，为什么以前没做成？ | 变化 → 新能力/成本 → 客户结果 → 已出现信号；因果链或时间线 | `AI 正在重塑一切`、窗口只靠“没有大公司” |
| 产品与机制 | 产品具体替客户完成哪一步，为什么更好？ | 简化产品流程、真实演示、输入/动作/输出/责任人 | 架构截图、功能列表、隐藏人工环节 |
| Traction | 哪些有价值的行为已经发生并重复？ | 期间收入/活跃/付费、cohort、留存、使用深度；主图 + 一个辅助证据 | 累计下载、无分母百分比、跨口径转化、三张小图各讲一件事 |
| 市场与切入 | 先赢哪类客户，规模如何自下而上长出来？ | 客户数 × 可用于本问题的年支出；TAM/SAM/SOM 分开；wedge → 相邻扩张 | 行业总产值乘份额、目标渗透率塞进 TAM、GMV 当收入 |
| 商业模式 | 谁付、付什么、多久付一次，公司留下多少？ | 定价、费率、交付成本、续费/扩张；收入桥或单位经济瀑布 | 三条收入线无重点、实施费塞 ARR、未知毛利写假数 |
| GTM | 首批客户从哪里来，为什么能重复？ | 渠道动作、销售周期、转化漏斗、买家与使用者；实际数量和时间窗 | `线上营销/渠道合作`空话、自然流量却不讨论可复制性 |
| 竞争与防御性 | 客户为何选你，优势为何能持续？ | 直接与间接替代、客户选择标准、迁移成本；对比表或有依据的 2×2 | 只列 logo、雷达图全满分、`AI 算法/先发`即护城河 |
| 团队 | 哪些经历证明这支队伍会解这道题？ | 本人负责的动作与结果、可复用能力、关键岗位分工 | 顾问撑场、公司 logo 当个人能力、虚构使命故事 |
| 财务与资本效率 | 经营是否健康，预测由什么假设驱动？ | 有数据时给收入质量、毛利、burn、runway、关键假设；没有则列缺口 | 精细到月的假预测、run rate 当收入、以建议预算冒充真预算 |
| 融资请求与里程碑 | 多少钱买到哪些可验收的新证据？ | 金额 + 用途 + 时间 + 里程碑 + 下一阶段可融资/经营状态 | 随意 55/20/20/5 分配、只有招聘和功能列表 |
| Vision | 若关键判断成立，五年后建成了什么？ | 从当前 wedge 到更大业务的具体扩张逻辑 | 用愿景掩盖当前无产品、无需求或无路径 |

## 四、关键板块的内容纪律

### 市场：可复算，也要能进入

- 写清第一批客户、触发场景、现有替代、时间/金钱/风险成本，以及谁有预算和决策权。优先真实付费、重复使用、主动寻找替代和昂贵人工绕路。
- 有 TAM 数字时交代时间、地区、潜在付费客户数、每位客户可用于此问题的年支出及来源。用付费单元向上加总，避免重复计算同一笔支出。
- 区分 TAM、SAM、SOM；平台交易额、客户预算和本公司收入不能混写，抽佣写 take rate。
- 数字后面接 wedge 与 GTM：先赢谁、靠什么渠道、为何能扩到相邻场景。算不稳时展示测算方法和缺口，不拼“千亿”占位，也不默认造 1,000/5,000/10,000 家企业的敏感性表填满页面。

### 非共识与 Why now

- 非共识不是刻意唱反调。指出常见解释漏掉哪个约束、客户或链路，并给出支持和推翻该判断的证据。
- 追问以前方案为何没有做大：成本、技术、分销、监管、支付意愿、供应链或组织流程，究竟哪项变了。
- 可以借用“变化 → 客户代价 → 新状态 → 产品机制 → 证据”的销售叙事检查断裂，但不机械变成五页；融资 BP 还要证明市场、团队、商业模式和资本效率。
- 必要时说明窗口何时关闭、谁可能快速跟进，以及没有窗口的替代解释。

### Traction：指标只证明它能证明的事

- 曝光证明传播；注册/候补证明兴趣；试用/调用证明开始尝试；留存证明持续使用；付费/续约证明付费需求；客户结果证明价值。不要把前一级包装成后一级。
- 优先期间数据而非只给累计曲线。比例同时给绝对值和分母；active 写动作和窗口；cohort 写起始时间、样本数和 W4/W8/M3 等口径。
- 早期小样本可以展示，但不要把小基数百分比放成唯一大标题。若比例比绝对行为更有信息量，必须保留 n、时间和样本来源。
- 同一页的图必须回答同一个投资问题。若当周 7 与月度 9 不能直接比较，选择一个口径进入主图，另一个进备注或另页；不要靠长脚注挽救一张混合图。
- 效率结果区分内部日志、客户自述和独立核验。`2 人各 2 天 = 4 人天`可计算；若当前值是`约 0.5 人天`，降幅也只能是约数。

### 竞争与防御性

- 直接竞品、间接替代和“什么都不用/人工继续做”都要进入比较。选择标准来自客户，不来自团队想赢的维度。
- 数据、网络效应、切换成本、渠道、供应链、监管资质或品牌只有在机制真实存在时才写。未来可能形成的写成`建设路径 + 当前证据 + 验证`，不写成现有壁垒。
- 客户数据跨客户训练、复用或去标识化必须有授权与合规依据，不能默认是数据资产。

### 团队：匹配与执行力，不堆砌履历

- 一号位与实际关键成员回答：本人做过什么、负责哪段、结果怎样、哪些能力能复用。大厂资源、连续创业成功与失败都要分清归因。
- 动机用真实选择、长期投入和具体取舍表达，不编使命故事，也不靠人格判断证明能扛周期。
- 有代表性成功或失败时，写`问题 → 当时归因 → 动作 → 结果 → 修正`。产品演示、客户采用、交付效率和过去承诺对照同样是执行力证据。
- 顾问不能替代创始团队；缺失的关键岗位写真实缺口和招聘计划，不虚构已经到位的人。

## 五、财务与融资请求：不制造“看起来完整”的数字

- 有真实财务时，保留收入确认、一次性/recurring、毛利成本边界、net/gross burn、现金与 runway 口径。预测必须能追到业务驱动因素和假设。
- 没有可靠数据时，给现状、融资目标和下一验证，不自动补三情景收入、月度利润、精确现金消耗、中间季度客户数或支出比例。
- 用户明确要求做假设模型时，单独标`建议模型 / 待创始人确认`，列出每个新增假设，不把建议内容混回公司事实页。
- 融资请求至少回答：金额、主要用途、可用时间（只有 burn 有依据时才写 runway）、这笔钱验证的里程碑，以及里程碑达成后的经营状态。
- 里程碑优先写客户、收入质量、留存、技术可靠性、交付成本和渠道重复性，不把“发布功能/招到人”当最终结果。

## 六、路演版与可转发版分开

| 维度 | `live pitch` | `forwardable / partner meeting` |
| --- | --- | --- |
| 首要目标 | 抬头即懂，创始人口播推进 | 不在场也能读懂核心论证并愿意转发 |
| 信息密度 | 一个观点 + 主图/演示 + 少量必要事实 | 一个观点 + 主图 + 1–2 个支撑模块 + 明确 so-what |
| 口径与限制 | 图注/来源保留必要项，细节进备注 | 页面可读地呈现关键口径，完整拆解进附录/data room |
| 页数 | 由时间和 5–7 个核心记忆点约束，不硬套阅读版 | 由证明责任决定，不为压页数缩字 |
| 附录 | 备问答，不在主线展示 | 放指标定义、 cohort、市场模型、财务假设、竞品与案例 |

两版可以同源，不应简单把转发版缩小字号当路演版，也不应把路演版的留白当成转发版“内容不足”。

## 七、常见借口与纠偏

| 借口 | 纠偏 |
| --- | --- |
| “投资人需要完整，所以每个栏目都要有数字” | 未知项标缺口和验证方法；假精确比空缺更伤信任 |
| “标成建议/情景，就可以自由补预算和预测” | 建议也是新增内容；只有用户需要假设模型时单独提供并列假设 |
| “高密度就是每页多几张图、多几个 KPI” | 一页一个投资判断；主图证明它，辅助模块补比较或含义 |
| “谨慎就要反复列不能证明什么” | 一处关键限制 + 备注追问 + 下一验证，其余删掉 |
| “像硅谷 VC 就要写 operating system / platform / zero-edit acceptance” | 用真实业务主体、动作和结果；术语只保留有明确口径的 |
| “用户说保留事实，所以原稿口号和愿景也必须保留” | 广告语和最高级不是事实；只有明确要保留愿景时才单列 Vision，不当当前能力 |
| “缺数据就先拿一页列 not known / not supplied” | 改成下一验证页，写具体取证动作；只有用户明确要缺口审计时才集中列缺失 |
| “来源行越完整越好，连无市场/竞品数据也写上” | 来源行只放 provenance、截止时间和必要样本口径；无关缺失进下一验证或删除 |
| “Airbnb/LinkedIn 就是这么融到的” | 案例有年份、轮次和语境；学论证，不复制数字、页序或成功因果 |
| “时间紧，可以先跳过事实账本和渲染审计” | 时间紧就减少页面与主张，不减少真实性和交付验证 |

## 八、暂停并重做的红旗

- 标题连读只是`市场 / 产品 / 技术 / 团队 / 财务`，复述不出投资论点。
- 首屏读完仍不知道公司为谁做什么，或当前产品与远期愿景混在一起。
- 同一页出现两个以上互不相同的主张，或三张图各自回答不同问题。
- 为了填市场、财务、融资用途而新增无依据数字，即使标了“建议”。
- 百分比没有绝对值/分母，active 没有动作和窗口，cohort 没有样本口径。
- 同一限制在标题、三条要点、图注和备注中反复出现，页面没有下一验证。
- 英文标题变成标签拼接，正文充满`seamless / robust / operating system / human gate`等伪地道表达。
- 实际 PPTX 没有经过内容、渲染、几何和文件核验，或只交大纲却声称完成 PPT。

## 九、交付前自查

- [ ] 一句公司定义和 3–5 句投资论点都能被外人复述，每句有证据与反证。
- [ ] 已明确 concept-driven 或 data-driven；最强证据和最大异议放在合适前序。
- [ ] 产品、 traction、商业模式、市场、竞争、团队与融资用途都承担明确证明责任。
- [ ] TAM 可复算，收入/GMV、bookings/revenue、一次性/recurring、实际/run rate 不打架。
- [ ] 图表同期、同单位、同分母；绝对值与比例同在；来源、时间、样本和派生公式可查。
- [ ] 团队经历能区分个人能力与前平台资源；防御性写成机制而非形容词。
- [ ] 融资请求连接可验收里程碑；没有以“建议”为名补出无依据预算、预测或中间目标。
- [ ] 路演版与转发版密度适配场景；附录能支撑合伙人追问和 data room。
- [ ] 中英文均为直接业务语言；案例引用带公司、轮次、年份、来源，不神化 deck。
