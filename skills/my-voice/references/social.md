# 公开写作：Roy Tong 的表达

当前没有可用的用户亲笔文风样本。[已确认的偏好与校准方法](voice-calibration.md)是起点：用户喜欢王小波的独立思考、故事感、幽默和反讽，并认为半佛仙人、葬AI吸引人的关键是**活人感**。下面是据此拟定的创作方向，不冒充用户原本的口吻。其他作者的具体做法见[技法工具箱](creator-techniques.md)。

## 活人感从哪里来

- **有自己的取舍。** 文章要能回答“我为什么看这件事、哪里让我不服气或好奇、读者该重新看哪个问题”。写出基于材料的判断，别把各方说法平铺成中立简报；证据不足时可以清楚地保留疑问。
- **让思考发生在纸面上。** 给读者看一个具体场景、奇怪的细节、预期与结果的落差，再把它带到技术或商业机制。王小波式的启发在于对习以为常的说法多问一步，并让推理本身有趣；不仿他的句法或现成笑话。
- **允许真实的反应。** 惊讶、怀疑、好奇、烦躁可以在有具体对象时出现。写“这项指标把失败后的人工接管藏起来了”比贴“令人震惊”更有力量；不要代用户编造当时的心情。
- **句子有呼吸。** 解释处让句子走完，转折处可以短下来。可以有口语、反问和反讽，但不按段落均匀撒梗。幽默优先从事实的荒诞或作者自己的判断里长出来，避免模仿博主口癖。
- **人站在证据旁边。** 亲历、团队经历、外部资料、合成示例和假设情境各用各的名称。一个没有亲测的产品观察仍可有立场；不能用“我试了”“我们发现”制造现场。

活人感的最低判据：删去姓名和品牌后，读者仍能看出作者在这篇里**选择了什么问题、对什么提出异议、愿意拿什么改变看法**。如果只剩资料排列和漂亮收尾，先修判断与叙事，再修辞。

## 按材料选择形态

| 形态 | 合适的推进方式 | 特别注意 |
| --- | --- | --- |
| 实测或审计 | 真实任务与方法 → 观察到的结果和失败 → 解释 → 读者可复查的材料 | 列出样本、版本和口径；别把一次测试写成普遍规律 |
| 产品判断 | 真实产品或标明的假设情境 → 用户要完成的任务 → 系统约束与取舍 → 适用条件 | 没测过就说没测过；不把未来设想写成已验证体验 |
| 行业、人物和组织 | 一个有来源的事件或样本 → 人与组织的选择 → 激励和成本 → 另一种解释 | 不用单个故事代替总体；清楚区分先后关系与因果 |
| 快讯、工具短评 | 新变化是什么 → 对谁的哪项任务有影响 → 一个验证方法或实际结论 | 材料只够短评就写短评；不硬扩成长文 |

同一篇可以混合形态，但要有一条主线。开头可以是场景、真实对话、怪现象或一个明确判断，尽早让读者知道讨论的矛盾；不规定“第一段必须放所有数字”。有数字时给足上下文；没有数字也不强塞。小标题、表格、叙事分隔符随内容选，不以某一种排版当作作者签名。

## 写作时的取舍

1. **先列材料身份。** 对每个关键例子标明：亲历、用户提供、外部来源、合成示例、假设或推断。若材料之间冲突，先核对；无法核对时保留冲突。
2. **写出本文独有的问题和态度。** 用一句话说明“什么常见说法让我想追问，读者看完后可能改变哪个判断或动作”。如果只剩一个泛泛主题，先找更具体的任务、产品或决定。
3. **给出推进，不复读论点。** 每一段带来新事实、新机制、新反例或新的适用条件。表格压缩对照信息，正文解释为什么这些差异重要。
4. **选择一种自然的结尾。** 可以落在可执行测试、尚未解决的问题、条件明确的判断，或供查证的材料。不要每篇都强行交付清单，也不要为了“金句”把已经说完的观点换词再说一遍。
5. **只借需要的技法。** 好奇心叙事、实测、利益链、演示步骤和外部材料解读，都有适用场景。选用技法后重新写出本文自己的问题和观察；不挪用他人的口癖、标题句型、段落骨架或俏皮话。

## 编辑尺度

- 标题点出具体对象和判断，可留真实悬念。别用“震惊”“颠覆”“行业变天”代替信息。
- 长短句交替由论证决定。需要解释时可以写长句，关键判断可以短；不要让每段以同款短句结束。
- “我认为”“我会”用于提出可供用户审定的判断与取舍，不用来伪装实验或情绪。引用他人观点时保留归属。
- 关键事实数字挂来源、时间与口径。简单列举不必把正文写成审计表；详细证据可放注释或附表。
- 比喻只在帮助读者理解机制时使用。绝不规定每篇要有比喻、自曝错误、历史类比、冷幽默或方法清单。
- 常见毛病是同一结论说三遍、处处“不是 A 而是 B”、加粗每个判断、结尾回环、反复自我找补。修的是重复和失真，不是机械数词频。

## 平台变形

- **公众号和博客：** 允许完整叙事、表格和来源段。篇幅由材料承担的内容决定，短而完整优于为字数加节。
- **短评和社交帖子：** 一条问题、一项变化或一次实测即可。能给原始链接、截图或复现条件时一并给；不能验证则说清来自何处。
- **小红书：** 开头可用具体结果或任务，正文短段，图文分别承担信息。标题不许承诺正文给不了的结论；来源放在实际可见的位置，不预写“见评论区”。表情和口语程度服从用户指定平台语境。

交付前问自己：这篇文章里，哪里能看出作者在思考、选择和承担一个判断？读者能不能感到好奇、转折或会心一笑？若答案都没有，先修主题与段落推进，再添加修辞。对新形成、尚未经用户确认的关键立场，在交付说明中简短标出，便于用户校准。
